Key Architectural Highlights

    Central User & Role Management: The User model acts as the central identity provider. It handles secure password hashing (generate_password_hash), tracking tokens, and multi-role assignments via a role field (admin, hospital, driver, patient, doctor, asha).

    One-to-One Profile Mapping: Using Flask-SQLAlchemy relationships with uselist=False and cascades (cascade='all, delete-orphan'), the base User model seamlessly links to specialized profiles (Patient, Doctor, AshaWorker, or Driver).

    Many-to-Many Hospital Specialties: An explicit association table (hospital_specialties) connects multiple hospitals to multiple medical specialties, allowing flexible filtering for patient care.

    Hospital & Geolocation Data: The Hospital model stores emergency contact numbers and geographic coordinates (latitude and longitude), which are essential for location-based hospital searches or ambulance routing.

    Patient Vitals & Medical Reports: The Patient model tracks biological metrics, emergency contacts, and dynamic age computation via a Python property, alongside linked file uploads (PatientReport).

    Schedules & Fleet Tracking: Specialized models like DoctorSchedule manage weekly availability windows, while Driver tracks real-time duty status and GPS coordinates.
